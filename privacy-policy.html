Privacy Policy

Last updated: September 30, 2026

Vault Approver ("the App") is a companion mobile application for Bitwarden cloud (bitwarden.com, bitwarden.eu) and self-hosted Vaultwarden/Bitwarden servers. This policy describes how the App handles your data.

1. Data We Collect

The App stores the following data locally on your device only:

  • Server URL (your self-hosted server, or bitwarden.com / bitwarden.eu)
  • Account email address
  • Encrypted authentication tokens (access token, refresh token)
  • Encrypted user key (the App asks for Face ID, Touch ID or fingerprint before it decrypts it)
  • Unique device identifier (randomly generated UUID)
  • Client certificate for mutual TLS (a .p12/.pfx file and its password), only if you import one for a self-hosted server that requires it — kept in the secure keychain for that server only
  • Two-step login "remember this device" token, only if you keep that option on — kept in the secure keychain for that server and account
  • PIN Shift vector, only if you choose to save it in the PIN tools — kept in the secure keychain of this device only; it is never shown again, synced or sent
  • User preferences (theme, language, lock timeout, refresh interval)
  • Request approval/denial history

2. Data We Do NOT Collect

  • Master password — entered once during setup, used to derive encryption keys, and immediately discarded. It is never stored.
  • Vault contents — the App cannot access, read, or display any passwords, notes, or other vault items.
  • Analytics or telemetry — no usage data, crash reports, or behavioral analytics are collected.
  • Location data
  • Contacts, photos, or any other personal data

3. How Data Is Stored

All sensitive data is stored in the device's secure storage:

  • iOS: Apple Keychain, "this device only" items that are available only while the device has a passcode and is unlocked
  • Android: encrypted shared preferences backed by the Android Keystore

Your user key is stored encrypted, and the App asks for your biometrics (Face ID, Touch ID or fingerprint) before it decrypts it. The secure-storage items themselves are protected by your device passcode and the operating system, not by a separate biometric-only lock, so keep your device protected with a passcode.

4. Network Communication

For your vault account, the App communicates only with the server you choose during setup: your self-hosted server URL or, if you choose Bitwarden cloud, Bitwarden's own servers (vault, api, identity and notifications hosts of bitwarden.com or bitwarden.eu). Communication uses HTTPS encryption unless you enter an http:// server address yourself; the App warns you before signing in over such an unencrypted connection. If you imported a client certificate, it is presented only to the server it was imported for, and the App does not follow redirects to other servers. The App connects to:

  • /identity/accounts/prelogin — to retrieve key derivation parameters
  • /identity/connect/token — to authenticate and refresh tokens
  • /api/auth-requests/pending (on older servers /api/auth-requests) — to fetch pending login requests, and /api/auth-requests/{id} — to approve or deny one
  • /api/two-factor/send-email-login and /api/accounts/resend-new-device-otp — only when you ask for an e-mailed sign-in or device verification code
  • /api/now — the server time, so request expiry follows the server's clock
  • /notifications/hub — WebSocket for real-time notifications

Apart from the optional cloud settings sync below, no data is sent to any third-party service, advertising network, or analytics provider.

The PIN tools (PIN 24, PIN Shift, YubiKey and the legacy mask) run fully offline on your device: nothing you enter there — seed phrases, passphrases, PINs, master keys or serial numbers — is synced or transmitted anywhere, and nothing is stored except a PIN Shift vector that you choose to save on the device (see section 1). PIN 24 can read a nickname list from a Ledger Passwords backup file that you pick yourself: only the nicknames and charset names are read, on the device, and kept in memory until the PIN tools are wiped; the file is never changed or uploaded.

5. Third-Party Services

The App does not integrate any analytics tools, advertising frameworks, or tracking services.

Optional cloud settings sync. The App includes Google Firebase (Firebase Authentication and Cloud Firestore) for one optional feature: keeping your App settings the same on your devices. It is off until you sign in to it under Settings → Cloud sync with Sign in with Google or Sign in with Apple. Only then does the App send to Firebase:

  • your Firebase account identity from Google or Apple (as handled by Firebase Authentication)
  • theme, language, lock timeout (except "never lock", which is never synced) and refresh interval, plus the time of the last change

Your vault account, server address, email address, keys, tokens, certificates, request history and login requests are never sent to Firebase. Signing out of cloud sync stops the sync; it does not affect your vault session. Settings → Cloud sync → Delete account deletes the sync account and its saved settings from Firebase (see section 7).

6. Data Sharing

We do not sell, share, or transfer your data to any third party. Your account data stays between your device and the server you chose; if you turn on cloud sync, your App settings are also stored in Google Firebase as described above.

7. Data Retention and Deletion

All data is stored locally on your device. You can delete stored data at any time by:

  • Using the Log out button in Settings — this erases your account's encryption keys, tokens, session data, request history and "remember this device" tokens. The device identifier, imported client certificates and a saved PIN Shift vector are kept (the device identifier so that the server recognises this device on the next sign-in); remove a certificate under Settings → Client certificate and the vector under PIN → PIN Shift → Delete
  • Using Delete account under Settings → Cloud sync — after you confirm with the same Apple or Google account, this permanently deletes your cloud sync account (Firebase Authentication) and the settings stored for it in Cloud Firestore, and revokes the App's Sign in with Apple authorization. Settings on the device, your vault account and everything else on the device are not affected. The App does not create Bitwarden or Vaultwarden accounts; delete such an account in your server's web vault
  • Uninstalling the App — this removes the App's data from the device. iOS may keep secure keychain items after an app is deleted; if you install the App again, it deletes those leftovers the first time it starts, before anything is signed in

Request history older than 30 days is automatically cleaned up.

8. Children's Privacy

The App is not directed at children under 13. We do not knowingly collect any personal information from children.

9. Security

The App implements the following security measures:

  • End-to-end encryption using RSA-2048-OAEP for key exchange
  • AES-256-CBC with HMAC-SHA256 for symmetric encryption
  • Argon2id or PBKDF2-SHA256 for key derivation
  • Biometric authentication required for every unlock
  • All cryptographic operations performed locally on device
